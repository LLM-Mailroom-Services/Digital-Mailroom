## API-leg naming schema

Reports are separated by specialist/task, never flattened across a model directory:

```
<this dir>/<model_short>/<task>/runs/<run_id>.md
<this dir>/<model_short>/<task>/RUN-<wave>-<CLASS>-<MODEL_SHORT>-REPORT.md
<this dir>/INDEX.md
<this dir>/API-LEG-MASTER-REPORT.md
```

`model_short/` is the decode-profile key if one exists, else the slugified model id. `task/` is the eval task id (`contracts`, `insurance_claims`, `correspondence`, `corporate_records`, `merger_agreement`, `classification`). `wave` is the draw size (`20`, `50`, …). The stem `RUN-<wave>-<CLASS>` pairs directly with the Modal report of the same stem in the sandbox tree — that is how you compare the two legs.

## ModernBERT ownership boundary

The ModernBERT reports are here, not in the sandbox. Per [`reports/modernbert/README.md`](https://github.com/LLM-Mailroom-Services/eval-environment/blob/main/reports/modernbert/README.md), `local-mailroom-sandbox` **only feeds weights** via `MAILROOM_ML_SRC` / `MODERNBERT_MODEL_PATH`; it does not own these write-ups. The sandbox tree's own [`reports/modernbert/`](https://github.com/Exios66/local-mailroom-sandbox/tree/main/reports/modernbert) is a redirect to this location, and the sorter cost basis is the measured OpenRouter runs under `api-comparisons/qwen3-8b/classification/` rather than sandbox fixtures.

<Callout type="warning">
The ModernBERT README carries an operational note dated 2026-09-27: **do not launch competing GPU jobs on the training host.** Follow the current README rather than this summary when scheduling work.
</Callout>
